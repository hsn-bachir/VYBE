2026-11-26 · PDF §3 item **10** · branch `feature/movie-night` · baseline **ea914aa**. Startup verified a clean checkout matching origin and no missing `origin/dev` commits. M5.7.2 was approved/committed/pushed by the operator. This slice remains uncommitted for source review.

## Implementation and design

- Added Movie Nights immediately after Library, with the existing animated indicator active across `/movie-nights`, `/movie-nights/new` and `/movie-nights/:nightId`. All three routes lazy-load inside the existing RequireAuth/AppLayout structure. Creation/detail share a minimal static placeholder; neither requests event details or exposes forms/actions.
- Dashboard uses VYBE's semantic tokens, typography, shared buttons, Avatar, MovieState, MoviePagination and React Bits AnimatedContent. Responsive cards have 1/2/2/3 columns at 390/768/1024/1440 px, text relationship/lifecycle badges, organizer and event-zone date/time. Long titles/usernames wrap without truncating important information.
- Authenticated navigation uses a second header row at widths up to 1099px; a scoped header-height token keeps Home hero alignment and Discover scroll offsets consistent. Guest navigation, account controls, focus behavior and reduced-motion handling remain intact. Document titles identify the Movie Nights section.
- My Movie Nights uses the existing server-side mixed listing, with All/Scheduled/Finalized/Cancelled filters and 12 entries/page. Invitations uses the independently paginated received endpoint. URL parameters `view=nights|invitations`, `status=all|scheduled|finalized|cancelled` and `page=1..10000` survive pagination, reload and browser history. Switching view/status resets page; invalid values show a recovery link without querying events.
- **Contract decision:** the received-invitations endpoint has no status filter. Status controls apply only to My Movie Nights. The inbox explicitly shows all event/RSVP statuses, preserves any selected dashboard status in the URL for returning to My Movie Nights, and never filters a partially loaded page. No global relationship counts/filters are inferred.

## Privacy, ownership and exclusions

The page reuses approved M5.7.2 hooks, owner keys, API adapters, permissions and timezone utilities unchanged. Only the selected view is queried, with no per-card detail/metadata requests. Event data stays in React Query, never independent component state. Cards explicitly render only common summary fields; pending/declined cards have no private-detail links, location, meeting URL, winner or totals. Accepted/host cards link to the static detail placeholder. Received cards show the server RSVP status.

Restricted verified accounts retain reads and see a restriction notice; they have no Create action. Unknown/unavailable/ineligible access, loading, empty, filtered-empty, out-of-range, invalid-URL, schedule-unavailable and retry states are supported. Existing authentication guards and legacy/Firebase session abstractions remain unchanged.

No backend/API/schema/auth/config/environment/dependency changes, migrations, provider integrations or deployment. No creation/edit forms, RSVP mutations, shortlist, voting or finalization interfaces. M5.7.3B and M5.7.3C remain unstarted.
