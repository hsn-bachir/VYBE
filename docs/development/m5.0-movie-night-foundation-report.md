## Delivered

Core-only additive migration creates `movie_nights`, `movie_night_invitations`, `movie_night_movies`, `movie_night_votes`. Models expose event/user/shortlist relationships and typed status/RSVP/date casts. The event query scope limits membership in SQL. Auto-discovered policy enforces host ownership, invitation visibility, accepted participation, active/verified account eligibility, exact start deadline and terminal state restrictions. No privileged-role bypass.

Reusable rules validate UTC instants/IANA zones and event fields, check scheduled/open state and same-event movie membership, and prevent removal of voted movies. Internal transactional RSVP and finalization transitions lock current actor then parent event, reauthorize, preserve votes after the deadline, clear votes on open-state decline, require valid votes, resolve highest count/tied leaders and save irreversible results atomically. These transitions have no HTTP adapters. No Catalog dependency is required for persisted votes or winner selection.

The [domain/schema/proposed API contract](../api/movie-nights.md) documents all requested subsequent endpoints, projections, validation, status codes, account/membership matrix, retention, migration deployment and mandatory write locking. API/schema indexes and roadmap link to it. Endpoints, controllers, FormRequests, Resources, user search, notification delivery, frontend and M5.1–M5.7 workflows remain unimplemented as requested.

## Decisions and remaining gates

Host is implicitly accepted; all invited RSVP states retain private view access, including cancelled/finalized events. Restricted participants retain read access; only active verified, activated accounts mutate. Editing/inviting/RSVP/shortlist/voting close at start; cancelling/finalizing remain possible afterwards while scheduled. Terminal states cannot be edited, cancelled or reopened through these rules. Unvoted nomination removal belongs to host or original nominator; voted movies are retained. A previously cast accepted participant's vote survives later account moderation. Host moderation can therefore block finalization until eligibility is restored.

Schema uses restrictive deletion, no automatic user/event cleanup and no cross-database FK. TMDB IDs are logical references, not duplicated metadata. Domain immutability is enforced through policy/transitions; direct SQL/model writes can bypass it. All later mutations must use the documented parent event lock and fresh account checks; database checks alone do not freeze history.

Before M5.1, review the proposed REST contract and these assumptions: no terminal edits or host transfer, HTTPS meeting links, proposed caps of 50 shortlist entries/200 invitees, participant-visible safe invitation list, no retrospective vote invalidation on moderation, no notifications yet. Define retention and any exceptional host recovery separately. Apply the Core additive migration through the normal reviewed deployment process before enabling future endpoints. Rollback with real event data is destructive and needs an approved retention plan. No live/development migration has been applied.

## UTC persistence review fix — 2026-11-23

The review blocker was reproduced on real PostgreSQL: under `SET TIME ZONE 'Asia/Beirut'`, the original model writes shifted `starts_at` by two hours in winter and three hours in summer. Both new regression tests failed before the fix.

The model-scoped `HasMovieNightUtcTimestamps` concern now normalizes Eloquent date values to UTC, writes an explicit `+00:00` offset on PostgreSQL, and converts offset-bearing PostgreSQL reads to UTC without changing their absolute instant. All four Movie Night models use it. It covers `starts_at`, `finalized_at`, `cancelled_at`, `responded_at` and all automatic `created_at`/`updated_at` values, including touch updates. Other drivers retain the normal Laravel SQL date format with UTC-normalized values. Existing second precision is unchanged. No global PostgreSQL timezone, database config, schema, environment, authentication or other module changes were made.

- Updated `backend/app/Models/MovieNight.php`, `MovieNightInvitation.php`, `MovieNightMovie.php`, `MovieNightVote.php` to use it.

- Updated `docs/api/movie-nights.md`, `docs/database/schema.md`, this report and `PROJECT_ROADMAP.md`.

Tests leave the session in `Asia/Beirut` throughout writes and reads, verify independently stored epoch values plus UTC model values in winter/summer, and restore the previous session timezone in a finally block. A deadline test verifies voting one microsecond before start, exactly at start and after start; finalization still uses the preserved earlier vote. No new endpoints or M5.1 functionality were added.

Persist date fields through model save/instance update/touch paths. Raw SQL/bulk date assignments bypass Eloquent conversion and require explicit-offset instants.
