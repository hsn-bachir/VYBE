# VYBE M2.1 engineering report

Date: 2026-10-31. Implementation and local verification complete on `feature/personal-library`, based on `ad33da3` (completed M2.0). No commit, push, branch switch, merge or PR was performed. Hosted CI and human review remain delivery gates.

## A. Repository findings

The existing application is a React SPA, Core Laravel API/BFF with Sanctum sessions, and an independently runnable Laravel Movie Catalog. Core owns user data; Catalog owns movie metadata and TMDB access. The existing batch endpoint/client, auth hooks/guards, Axios instance, TanStack Query, MovieCard/Image/Grid/Pagination/State, shared Button, AppLayout, logo, palette and React Bits AnimatedContent were reused.

Source inspection confirmed that popular/search results persist their summaries before returning, and details hydrate full metadata before returning. New related results follow the same persistence rule. Therefore normal displayed selections can be confirmed through the cache-only batch boundary. An uncached valid ID is not proof of a nonexistent TMDB movie; opening details is the existing bounded hydration path. No cross-database query or foreign key was added.

## B. Backend implementation

- Core adds `watchlist_entries` and `watched_movies`, owner FKs with cascade deletion, unique `(user_id, tmdb_id)` keys and owner/timestamp/id ordering indexes. Models expose only approved writable fields. The existing User model adds two HasMany relationships.
- Seven private routes implement list/add/remove for both lists and a movie library-state singleton. They use session authentication, verified-email enforcement, CSRF even without Origin, no-store/private responses including errors, and per-owner limits (120 reads/minute; 60 writes/minute shared across lists). CORS now permits DELETE for the configured frontend. Missing Accept headers still yield JSON 401/403 rather than a missing-login-route error.
- New additions validate strict integer IDs and confirm Catalog persistence once. Unresolved references return explanatory 422; Catalog failures return sanitized 503. Duplicate additions return 200 without Catalog and preserve all timestamps. New rows return 201. Absent or present removals return 204 without Catalog. `firstOrCreate` and the database unique key handle concurrent insert races.
- Watched time is the first successful mark in UTC. A duplicate does not alter `updated_at`; removal and a subsequent add create a new first-mark time. Both lists are independent.
- Lists paginate before enrichment, default 20/max 50, using a single batch call for a nonempty page. Summary order is mapped back to Core order; missing metadata and complete Catalog outages preserve memberships and totals. Empty pages and state reads make no Catalog request.
- A summary-specific timeout defaults to 3 seconds (configurable 1–5). A deliberately stalled local HTTP server measured **3.08 seconds** for summaries and **12.01 seconds** for unchanged detail/discovery timeout behavior. No Core retry was added.

Contracts: [personal library](../api/milestone-2-contracts.md), [database schema](../database/milestone-2-schema.md), [batch summaries](../api/catalog-batch-summaries.md).

## C. Movie details enhancement

The new layout has a cinematic backdrop/poster hero, title/tagline, visible TMDB rating, genres/runtime, trailer CTA and independent personal actions. Story/director information and structured facts follow, then a trailer preview, cast strip and related cards. The layout uses existing VYBE branding and tokens and was inspected at 375, 768 and 1440 pixels.

Catalog appends videos/credits/recommendations to its existing TMDB detail request. A separate additive experience endpoint carries a safe trailer, at most twelve cast members, four directors and six provider-related movies. Base detail DTOs remain unchanged. Related summaries persist before return, so saving them works with reference validation.

Only valid YouTube Trailer/Teaser keys are accepted; official trailers have priority. Empty/unsupported media produces an honest unavailable state. Existing cache infrastructure retains extras for up to 30 days, fresh for the configured detail TTL (seven days by default), with a shared per-movie lock, refresh cooldown and stale fallback. No relational media tables or extra service were introduced.

The native modal/player chunk loads on demand. The iframe uses a constructed, validated `youtube-nocookie.com` URL. There is no YouTube request before play. Keyboard activation, Escape/close, iframe unmount and focus restoration were exercised. An external playback link remains available for provider restrictions. See the [full media contract](../api/movie-experience.md).

## E. Frontend implementation

`features/library` contains API methods, DTOs, hooks, actions, page, styles and tests. `/library` redirects to watchlist, with separate protected watchlist/watched routes and a minimal Library navigation link.

Numeric owner-scoped keys are `['library', userId, kind, page]` and `['library', userId, 'state', tmdbId]`. The media key is `['movies', 'experience', tmdbIdString]`. Successful mutations update only the confirmed affected field and invalidate that owner's matching list and movie state. They do not invalidate movie discovery or mutate the other membership. Writes do not retry automatically; controls disable while pending. Auth changes cancel/clear private caches; pending operations and callbacks check account identity.

401/403 recheck auth; 419/422/429/503/network failures have contextual sanitized feedback. Empty lists, individual missing metadata, Catalog outages and Core failures have distinct states. Missing entries expose their actual TMDB ID and removal. Watched dates render using semantic time elements. Removal feedback remains accessible after the card disappears and focus moves to the list heading. Existing cards keep actions outside the movie link.

Details, Library and the trailer dialog are lazy chunks. Final initial JS: **497.27 kB / 167.77 kB gzip**, with no Vite chunk-size warning. Details: 10.54 kB; Library: 4.08 kB; trailer dialog: 1.46 kB (plus shared chunks). No provider SDK was added.

## H. Known limitations and deployment

- Live TMDB credentials/provider delivery and actual third-party YouTube playback were not verified. Deterministic tests verify normalization and player construction; video removal, embedding restrictions and region policy remain provider-controlled. Unsupported/missing trailers show no fake CTA.
- Extras use the existing en-US provider request and may be unavailable for a movie. Related content is provider-derived, not personalized. Stale extras stop being available after cache retention expires.
- Offset pages can shift during concurrent edits; media caches share the existing Catalog availability boundary. The test server's latency numbers are local measurements, not production capacity benchmarks.
- Swipe/particle/WebGL interactions were deliberately deferred. Screen-reader behavior was reviewed through semantics/live regions and keyboard checks, not a full assistive-technology audit.
- Instructor confirmation of the two-backend microservice grading expectations remains outstanding. Collections, ratings, reviews, profile editing and production OAuth remain out of scope.

Deployment sequence: deploy Catalog experience support; run `cd backend && php artisan migrate` against the intended Core database through the normal reviewed deployment process; deploy Core/frontend and rebuild configuration if deployment caches it. Configure the existing service URL/token and optionally `MOVIE_CATALOG_SUMMARY_TIMEOUT_SECONDS=3`. No new Catalog migration is needed. Existing `FRONTEND_URL`/Sanctum cookie settings must match the deployment. No production migration or deployment was performed here.
