## Security and privacy

- Minimal pending/declined summaries form a separate discriminated type from accepted summaries and private Event detail. Location/meeting URL exist only on Event detail. Participant projections reuse the backend's id/username/avatar allowlist.
- All queries and mutations have Core owner-scoped keys. Filters, event IDs, endpoint kind and pagination distinguish queries. Hooks reuse `useAuth` and `useAccess`; restricted verified accounts can read, while permission helpers offer writes only to active verified accounts. There is no provider-specific identity logic, bearer token or localStorage authentication, preserving both legacy and Firebase session compatibility.
- Guards capture session and revocation generations before requests. They check before dispatch, after CSRF and after response, rejecting obsolete responses even if transport cancellation is ignored. Logout, owner switch, verification change and known banned/deactivated access remove Movie Night query/mutation cache entries. Leaving and returning to the same owner does not revive a previous generation.
- Successful decline immediately removes private detail/shortlist/votes/roster/lookup caches and mixed list/inbox caches that might retain accepted-only summary fields. Acceptance also discards old projections and requires fresh reads; it never restores an old vote. Failed RSVP is not applied optimistically.
- Denied 401/403/404 requests conservatively purge event caches and mixed summary projections (401 purges the owner). Auth/account failures also refresh shared auth truth. Candidate-not-found and action-forbidden errors may therefore evict more data than strictly necessary; a fresh authorized read restores it. Revocation advances the generation before cancellation, preventing late private reads, list responses and mutation responses from restoring removed data. Mounted query observers are reset before cache removal, clearing previous successful private results.
- Query and mutation retries are disabled. Private queries have zero stale/GC time and no previous-owner placeholder data. Existing shared logout cleanup already classifies this query family as private. Private mutation records are removed on revocation and their mounted observers are explicitly reset, clearing data, error, variables and callbacks from the current result.
- Cancellation/finalization immediately apply the returned authoritative Event to existing accepted detail caches; other mutations invalidate server data. No totals/winners or optimistic permission changes are calculated locally. Finalization requires a literal `confirmed: true` and runtime check in the hook command. No automatic finalization is attempted. Actual user confirmation UI remains a future requirement.
- Error handling retains `MOVIE_NIGHT_TIE`, valid authoritative TMDB leader IDs, validation fields, stale-selection detection and Retry-After. Tie/stale/409 failures refresh event queries without resubmitting writes or choosing a replacement winner. Other messages use safe shared normalization.
- Permission helpers are advisory and require an owner-scoped server projection. They do not authorize access or infer membership for outsiders. Start equality closes RSVP/edit/invite/nomination/vote hints; host cancellation/finalization remain possible while scheduled after start. Terminal states close mutations. Candidate removal requires a known authoritative zero count and eligible host/nominator.

## Date/time behavior

Browser timezone is a suggestion only; callers must pass an explicit valid IANA timezone. Local wall times convert to strict second-precision UTC `YYYY-MM-DDTHH:mm:ssZ`, independent of the machine's local timezone. UTC display accepts the backend's fractional-second timestamps. Preview displays the chosen event zone. Invalid calendar dates are rejected.

Offset candidates on both sides of nearby transitions are round-tripped against the requested wall time. Gaps return no instant and cannot be silently shifted. Overlaps return both instants and require an explicit earlier/later choice. Tests cover Beirut winter/summer, Kathmandu's fractional offset, New York/Berlin gaps and overlaps, Lord Howe's half-hour transitions and Apia's skipped day. Timezone rules come from runtime Intl/IANA data; future political changes require current browser timezone data. No extra date dependency was introduced.

### Root causes and corrections

1. **Invalidation scope:** `purgeNight` previously incremented the global session generation for an individual event and removed every mutation belonging to the owner. That correctly rejected old mixed summaries but also rejected unrelated event responses and successful writes. Session identity generation is now independent of per-owner access generation, per-event access generation, per-event read revision and separate list/inbox generations. Revoking event A changes only A access plus mixed-summary generations, removes only A mutation results (including a completed create response identifying A), and preserves event B reads, writes and observers. A create still awaiting its event ID is unaffected by an unrelated existing event purge. Owner-wide denial invalidates every scope for that owner; logout, account switch and known account-wide revocation clear the session's private state. Lifecycle refresh changes read revisions without marking server writes obsolete.

2. **Lifecycle application:** cancellation/finalization previously only invalidated queries, leaving successful detail caches scheduled until refetch. The returned authoritative terminal Event is now applied synchronously to existing detail entries with matching event ID and accepted membership, only for the still-current host owner. No new private detail cache is created, and other owners' entries are untouched. Advancing A's read revision and list/inbox generations before cancelling their old requests prevents stale detail, totals and summary responses from restoring scheduled state. Active list, inbox and A vote queries refetch; inactive ones are marked stale for their next read. Detail consumers immediately receive the server's status, voting-open flag and stored winning TMDB ID. Existing permission hints therefore close lifecycle controls immediately. The frontend never derives the winner from leaders/counts.

3. **Mounted mutation privacy:** source inspection and a control regression reproduce React Query **5.101.4** behavior: `MutationCache.remove()` leaves attached `MutationObserver.getCurrentResult()` data intact. Movie Night now installs a feature-local mutation-cache subscriber before its hook can attach an observer. It tracks observer attachment/removal and explicitly calls the affected observer's public `reset()` when its Movie Night mutation record is removed. Reset clears the current data/error/variables and detaches the old mutation, so late results cannot repopulate that mounted consumer or fire its stale per-call success callback. Unrelated event B and other features' observers are preserved. Reusing a reset observer for B is tested while revoked A is still in flight. Private tie-leader errors are also cleared. No shared authentication module or React Query internals were modified.
