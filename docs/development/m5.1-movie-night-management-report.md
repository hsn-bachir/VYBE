## Implementation and ownership

Laravel Core now implements five endpoints under `/api/v1/me/movie-nights`:

| Method | Path | Success |
| --- | --- | --- |
| POST | `/api/v1/me/movie-nights` | 201 event detail |
| GET | `/api/v1/me/movie-nights` | 200 paginated event summaries |
| GET | `/api/v1/me/movie-nights/{night}` | 200 event detail |
| PATCH | `/api/v1/me/movie-nights/{night}` | 200 event detail |
| POST | `/api/v1/me/movie-nights/{night}/cancel` | 200 event detail; repeat 409 |

The controller uses FormRequests, explicit safe Resources and `MovieNightService`, reusing M5.0 models, policy/state rules and `HasMovieNightUtcTimestamps`. There are no new migrations, dependencies, configuration/environment edits or Catalog requests. M5.0 RSVP/finalization transitions remain internal and unchanged; no M5.2–M5.7 endpoints, notifications or frontend were added.

Create assigns the SQL host from the session actor and creates no self-invitation. Lists use SQL host/invitation scoping, status filtering, bounded pagination and stable starts_at/id ordering. Host/caller-only invitation relations are eager-loaded, with safe user projections and no per-event authorization queries. The list query-count test confirms equal query counts for one versus eight events. No provider latency or broader performance benchmark is claimed.

Detail/create/update/cancel return the documented safe detail projection; lists return summaries without location/meeting URL. Host fields are exactly id/username/avatar_url. Caller RSVP is implicit accepted for the host or the caller's invitation status. Other invitation records, emails, Firebase UID, roles, account status and personal activity are not serialized.

All writes use transactions and lock the current actor first. Update/cancel additionally scope and lock the parent event before checking state/deadline and M5.0 permissions. Validation is repeated inside the transaction, so a submitted future time is checked again after lock acquisition. Updates cannot resurrect a started or terminal event. Cancellation records its UTC timestamp and retains the event/invitations. It prevents later nomination/vote/finalization through the existing state rules/policies.

## Authorization and validation

Routes reuse the existing first-party `web`, `auth:sanctum`, `EnsureAccountAccess`, `EnsureVerifiedAccount`, `PreventAuthCaching` and read/write library throttles. Writes also require `EnsureActiveAccount`. Firebase UID mapping and session-version revocation are unchanged; compatibility tests exercise mapped/unmapped SQL users and current/revoked sessions, without contacting Firebase. Restricted verified members retain list/detail access but cannot write. Banned/deactivated/unverified accounts are blocked; pending activation is blocked by the movie-night policy. No admin/moderator bypass.

FormRequests reuse M5.0 event validation. Title is nonblank/max 150; timezone is valid/max 64; start must be a future strict UTC `YYYY-MM-DDTHH:mm:ssZ` instant; optional location is max 500 and meeting URL is HTTPS/max 2048. PATCH requires at least one editable field, preserves omitted values and permits null clearing of optional fields. Unsupported fields are rejected, including client-supplied host/status/winner/timestamps. Detail/cancel accept no request fields. Event IDs are canonical positive signed integers up to PHP_INT_MAX, malformed IDs return 422. List page is 1–10000/per_page 1–50 (default 20), with optional status only.

The existing exception responder now scopes safe 404/419/429/500 envelopes to Movie Night routes, preserving Retry-After and no-store/private headers. A forced SQL failure with application debug enabled verifies no database/event diagnostics leak. Pint also added braces/formatting to pre-existing auth/admin exception branches in the same bootstrap file; their conditions and behavior are unchanged.

## Contract decisions

No endpoint path or success-envelope deviation from [the contract](../api/movie-nights.md).

- Cancellation repeats return **409**, as the M5.0 contract explicitly specified; the effect is idempotent and the original cancellation timestamp is retained.
- Detail includes the safe host and caller RSVP, not a nested participant/invitation list. The separately documented invitation-list endpoint remains M5.2, as required by this slice's scope.
- Input dates use strict UTC Z strings, not local or arbitrary offset strings. Asia/Beirut is retained as display/DST context. Clients resolve local time into an unambiguous UTC instant before submitting. Output uses Laravel ISO UTC timestamps with fractional seconds.
- Edits must occur before the original start. A request cannot move an already-started event into the future. Scheduled events can be cancelled after start, but finalized/cancelled events cannot be changed.
- As in M5.0's protocol, state checks precede mutation policy checks after membership scoping. A member attempting a closed-state mutation receives 409; outsiders receive a hidden 404 regardless of event state.

## Manual verification instructions (not performed on application data)

Use a disposable development instance with the M5.0 migration applied and an eligible verified test user. Do not reset a shared database. Authenticate through the existing Firebase/session flow and bootstrap `/sanctum/csrf-cookie`; send credentialed JSON requests and the X-XSRF-TOKEN header for writes.

1. POST `/api/v1/me/movie-nights` with a future instant, for example `{ "title":"Friday cinema", "starts_at":"2027-07-16T18:00:00Z", "timezone":"Asia/Beirut", "location":"Living room", "meeting_url":"https://example.com/room" }` (choose a later date if needed). Expect 201, caller as host, accepted my_rsvp, scheduled status and no self-invitation.
2. GET the base URL and `/{id}`. Expect a safe paginated summary and detail respectively. Confirm UTC dates and no host email/UID or invitation roster in JSON.
3. PATCH `/{id}` with `{ "title":"Saturday cinema", "location":null }`. Expect the supplied edits and preservation of other values. Submitting host_user_id, status, or internal timestamps must return 422.
4. Sign in as a different noninvited test user, including an admin. GET/PATCH/cancel that ID must return the same 404 envelope as an unknown ID. Invitee behavior is tested with SQL fixtures only until M5.2 adds invitation endpoints.
5. As host, POST `/{id}/cancel` with `{}`. Expect 200, cancelled_at and voting_open=false. Repeat for 409; verify the original timestamp remains and the event still appears under `?status=cancelled`.
6. Missing CSRF must return 419. An unverified/banned/deactivated account must receive existing account gates; a restricted member can read but cannot write. Use the automated tests for exact deadline/terminal/rollback behavior rather than editing production time or data.
