## B. Database

New additive Core migration: `backend/database/migrations/2026_11_03_000002_create_reviews_table.php`.

- `id`, Core `user_id` FK with cascade deletion, unsigned `tmdb_id`, TEXT `body`, boolean `contains_spoilers` default false, Laravel timestamps.
- Unique `(user_id, tmdb_id)` enforces one review per owner/movie, independently of ratings.
- Index `(tmdb_id, created_at, id)` supports public newest-first pagination. The unique index also supports owner/movie lookup and future review counts.
- No Catalog FK, metadata copy, rating/library relationship, soft deletion, history or moderation fields.
- `Review::user()` and `User::reviews()` implement ownership. Fillable fields are only tmdb_id/body/contains_spoilers; casts give integer movie IDs and boolean spoiler flags. User identity is supplied through the authenticated relationship.

Validation accepts 1–5000 Unicode code points after trimming Unicode edge whitespace; TEXT under the existing utf8mb4 connection accommodates the bound. Existing timestamp precision is retained. Edits preserve ID/created_at; rendering also keys on body/flag to reset spoiler state after same-second edits.

SQLite and isolated MySQL 8.0.43 checks cover defaults, indexes, uniqueness, cascades, independent data and migration rollback/reapply. Rollback drops only reviews. No shared database was reset. After isolated verification, the single additive migration was applied successfully to normal local `vybe_core` so the running application has the table.

## C. Backend

All paths are under `/api/v1` and retain approved `data`/`meta` envelopes.

| Method/path | Behavior |
| --- | --- |
| GET `/movies/{tmdb_id}/reviews` | Guest-readable paginated reviews with public author; newest created_at DESC/id DESC |
| GET `/me/reviews/{tmdb_id}` | Verified authenticated owner's review, or `data: null` |
| POST `/movies/{tmdb_id}/reviews` | Verified create, 201; duplicate 409 `REVIEW_EXISTS` |
| PATCH `/movies/{tmdb_id}/reviews/{review_id}` | Verified owner/movie/id-scoped partial edit, 200 |
| DELETE `/movies/{tmdb_id}/reviews/{review_id}` | Verified owner/movie/id-scoped permanent deletion, 204 |

ReviewRequest reuses canonical decimal route identity validation (1–2147483647). Public list accepts only page 1–10000 and per_page 1–50, default 20. Other endpoints reject query fields. POST/PATCH require JSON, an allowlisted body and strict boolean when supplied; strings, integers and null are not booleans. Create requires body and defaults spoilers to false. PATCH requires at least body or flag, preserves omitted values, accepts false, and rejects empty/whitespace/null body. Client-supplied owners, IDs, timestamps, ratings and moderation keys are rejected.

Writes and own reads reuse explicit web session/CSRF, Sanctum, EnsureVerifiedAccount and private no-store. CSRF is enforced even without Origin. Private reads share library-read (120/minute/user), writes share library-write (60/minute/user); public reviews share community-read (120/minute/IP) with ratings. Existing credentialed CORS supports POST/PATCH/DELETE. Every review response prevents storage. Safe JSON 404/419/429/unexpected 500 handling works in debug mode and preserves Retry-After. Guests get 401, unverified users 403; non-owner, wrong-movie and absent reviews have the same 404. Repeated deletion is 404.

ReviewService checks the owner/movie singleton before Catalog. Existing duplicates return the exact 409 without network validation or overwriting timestamps/body/flag. A new reference uses `LibraryMetadata::confirm()`: persisted movie succeeds; cache miss is unresolved 422 with Details guidance, not a confirmed TMDB 404; unavailable Catalog yields safe 503. Reads, edits and deletes never call Catalog. Valid unknown movie lists return empty results.

The unique key remains authoritative under races. Duplicate SQL insertion maps to ReviewExists/409. Creation runs a short local transaction after HTTP; PATCH/DELETE lock the owner/movie/id row with bounded deadlock attempts. Partial concurrent edits apply only supplied fields; there is no revision/history contract. Public lists eager-load only user id/username/avatar_url and use three SQL queries when nonempty (count, rows, authors), no N+1 or Catalog calls. ReviewResource never exposes email/password/session fields.

## D. Frontend

New `features/reviews` supplies typed API/types/hooks, CommunityReviewsSection, ReviewEditor, ReviewCard, DeleteReviewDialog, semantic CSS and tests. The section is lazy-loaded after Community Ratings and before related movies. Public reviews are independent of private auth failures. Guests retain the existing sign-in return destination; unverified users use existing verification. Writing requires no rating or library membership.

The personal panel fetches the own singleton, then offers write/edit/delete. The controlled editor prepopulates confirmed values, counts trimmed Unicode code points, shows field errors/pending state, and preserves drafts after failed writes. A 409 refreshes own/public data while retaining the creation draft and requires explicit existing-review editing; POST never silently becomes PATCH. Confirmed success alone closes the editor and shows success. Deletion uses accessible confirmation; failure preserves the dialog and review.

Query keys use numeric IDs:

- Public prefix: `['movies','reviews',tmdbId]`; page: `['movies','reviews',tmdbId,page,perPage]`.
- Personal: `['me',userId,'review',tmdbId]`.
- Mutation: `['me',userId,'review-write',tmdbId]`, serialized scope per owner/movie.

Public pagination uses 20 per page, previous/next controls, true totals and an out-of-range recovery action. Reads forward AbortSignal, staleTime 30 seconds, no automatic retries/focus polling. Writes bootstrap CSRF, guard the current account before dispatch and before/after cancellation, set confirmed own data and invalidate only own state plus public pages for that movie. Create/delete return to page one; edits do not reorder. Ratings, metadata, discovery and Library/Collections keys are untouched. Auth changes retain existing cancellation/cache clearing; account-keyed components discard drafts. Stale callbacks cannot set another account's state. 401/403 remove affected private state and refresh auth; no write replay is added.

## E. Spoiler protection

The boolean flag persists independently of body text. Concealed review text is absent from DOM and accessibility output; only a neutral placeholder, warning and labelled Reveal control are rendered. Reveal/Hide is keyboard operable, per review instance, with aria-expanded/controls. Long text is collapsed with explicit Read full review/Show less after visibility is permitted.

The body component key contains movie ID, review ID, updated_at, body and flag. Movie/content changes and edits reset reveal state, including edits within one timestamp second. Hide removes the body again. The short blur-to-clear effect runs only after explicit reveal, with reduced-motion removal. CSS is not the concealment boundary.

React renders body as escaped plain text with preserved line breaks; HTML/JavaScript and Markdown are not executed. API review bodies are public even when marked spoilers. This is a reading preference, not privacy, encryption or an authorization mechanism.
