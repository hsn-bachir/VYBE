# M3.1A engineering report

## Scope and reuse

This slice extends Core's Sanctum session, verified-account middleware, protected M2 routes, User model, and existing write services. React reuses the shared Axios client, auth query, protected routes and AppLayout. Catalog and its database are unchanged.

## Implemented

- Core migration adds role and account status with safe defaults, CHECK constraints, and an indexed status/role lookup. Privileged fields remain outside User's fillable allowlist; registration rejects them explicitly.
- Fresh account-state middleware covers protected Core library, collection, profile, rating and review routes, plus authenticated identity/verification reads and resend. Logout is exempt. Banned/deactivated login returns generic 401.
- Active-account middleware denies restricted rating PUT/DELETE and review POST/PATCH. Restricted users can delete their own review. Write services lock the current user row and recheck state within transactions, including after Catalog validation.
- Laravel gates distinguish admin read, moderation read and active privileged writes. `EnsureRole` is available for future admin routes; no placeholder admin API routes were added.
- `GET /api/v1/me/access` exposes only role and status through a private no-store response. `/api/v1/auth/me` retains its five fields.
- `php artisan app:provision-admin {user_id}` promotes a specified existing verified active user when no other admin exists. Run it from trusted Core server access after `php artisan migrate`; it does not create a user or accept a password. Repeating with the same ID succeeds without a new change; another ID is rejected.
- React adds a user-scoped access query and lazy `/admin` landing. Admins and moderators have distinct landing copy, users receive access denied, and navigation follows confirmed access. The route waits for a fresh access check before displaying privileged content.

## Verification and limits

Backend PHPUnit tests cover defaults, invalid values, rollback, registration, access response, retained sessions, restricted writes, a state change during Catalog validation, initial provisioning and gates. Frontend tests cover access query, role decision and safe error mapping. A stateful Playwright fixture in `frontend/tests/access.browser.mjs` exercised guest redirect, admin/moderator landing, browser refresh, a retained banned session, logout/account switch and ordinary-user denial with no page errors; screenshots were inspected at 375, 768 and 1440 pixels. A separate real browser-to-Core journey used a newly migrated disposable SQLite database and verified CSRF login/logout, the no-store access DTO, retained-session ban enforcement, admin/moderator access, and ordinary-user denial with zero page errors. No Catalog or TMDB integration was claimed. Docker was unavailable, so isolated MySQL migration verification and hosted CI remain open. M3.1B/C user-management and invitations, M3.2 moderation, and M3.3 recommendations are pending.

Final local gates: Core `php artisan test --compact` passed 315 tests / 2800 assertions; focused AccessFoundationTest passed 10 tests and EmailVerificationTest passed 6 tests. Frontend `npm run lint`, `npx tsc -b --noEmit`, `npm test` (172 tests) and `npm run build` passed. `node .playwright-mcp/m31/browser.cjs` passed the stateful fixture with zero page errors; `node .playwright-mcp/m31/integration.cjs` passed the real Core/SQLite session journey with zero page errors. The initial JS chunk is 502.30 kB / 169.01 kB gzip, compared with the M2.5 report's 499.58 / 168.36; Vite reports its 500 kB chunk warning.
