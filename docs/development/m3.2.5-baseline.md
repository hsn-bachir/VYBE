# M3.2.5 performance baseline

Captured 2026-11-06 on the existing local development servers (`localhost:5173` Vite, `:8000` Core, `:8001` Catalog), before M3.2.5 edits. Branch `feature/admin-ui` at `d9d8b29` was clean. These are local development observations, not production or cold-cache claims. Public read-only endpoints were sampled five times with curl; the browser was an isolated guest context. No developer database was changed.

The sampled Catalog responses were 200, but their cache hit/miss state was not exposed. The first Core samples may reflect process or cache warming and are not controlled cold-cache measurements. Core-only review/rating reads around 330–350 ms and Catalog reads around 300–325 ms suggest substantial local Laravel development request overhead. Core movie proxy responses add a second service request and are around 670–750 ms warm. This is evidence of the total path cost; it does not yet isolate framework, SQL, cache or TMDB time. Query counts and SQL timings remain to be measured on disposable data before any database-specific optimization.

In an isolated guest Chromium session against Vite, hard navigation until the relevant page heading/region appeared took about 1,460 ms for Home, 1,422 ms for Discover and 2,937 ms for Movie Details. Each page started with `/auth/me`; network resource entries showed a cancelled first request and another request around 800–950 ms, then an additional `/auth/me` around 1,000 ms as nested auth observers mounted. Movie Details began its Core detail request after auth resolution and its experience request after details, creating a visible waterfall. This is development-mode browser evidence, including React Strict Mode and a warm server; it is not a production median. The exact movie-image loading time and cast/trailer readiness were not captured in this pass.

Baseline production build: 241 modules, initial JS **505.67 kB / 169.65 kB gzip**, initial CSS **50.16 kB / 10.46 kB gzip** and hero WebP **124.36 kB**. Vite reports the initial JS chunk above 500 kB. Admin and moderation pages already build as lazy chunks; the issue is not evidence that those route files are eagerly imported. Functional rating controls, React Bits components and cinematic animations remain in the bundle and must be preserved.

Admin UX audit: `/admin` is a link-only landing; `/admin/reviews` renders full bodies in large cards; `/admin/reports` and `/admin/actions` render card-like rows; the shared admin navigation is a non-sticky horizontal line; `/admin/users` already has a table but its mobile fallback becomes repeated full-size cards. Forms require reasons for routine role, restore, spoiler, report dismissal and password flows. These are source/UI observations rather than latency measurements.

Measurement limits: no authenticated browser timings, action-to-confirmation samples, production-runtime timings, disposable MySQL `EXPLAIN`, SQL query counts, controlled cold-cache/TMDB timings or Catalog outage samples were available at baseline. Subsequent fixes will be compared only where the same setup can be repeated.
