# M3.3 implementation and verification

Implemented on `feature/for-you-recommendations`, beginning from a clean working tree. No commit, push or branch switch. The explicit M3.3 request authorizes this slice beyond the older M2 scope text in AGENTS.md. Read ADR 0003 and the checked-out contracts/source; graph transport was unavailable, so structural claims were verified with targeted source reads and searches.

Architecture, exact calculations, request/response shapes, cache/exclusion behavior, configuration and limitations are recorded in [the recommendation contract](../api/recommendations.md).

- Documentation: this report, recommendation API contract and links from API/architecture docs.

For You reuses MovieCard, skeletons, buttons, collection dialog, React Bits AnimatedContent, existing query/session/access handling, design tokens and responsive poster grids. Card actions issue writes only on demand, avoiding per-card library-state requests. All six section categories share one scored pool. Saved/watched/rated exclusion is enforced independently on the backend and synchronized immediately on the frontend. Dynamic sections are only emitted when evidence and eligible rows exist.

## Checks

Provider HTTP was faked throughout automated tests. Core tests use disposable in-memory SQLite; Catalog uses its existing guarded disposable test trait. No shared databases were migrated or cleared. No migration was added. Local MySQL was not listening on port 3306, so separate MySQL migration verification was not performed.

Frontend lint, TypeScript, production build and the complete frontend suite pass. Browser acceptance uses isolated mocked Core HTTP and reduced motion. It passed at 1440/1024/768/390px without horizontal overflow; screenshots were captured at each width, including missing-poster behavior. The 390px screenshot was visually inspected. The repeatable browser test also verifies save removal, exclusion after reload, 503/retry recovery, honest cold start, empty state and guest redirect. These browser fixtures establish frontend behavior; backend exclusion correctness is separately tested with fake Catalog HTTP.

Core coverage includes positive/negative/neutral/conflicting actions, sparse confidence, contributor IDs, missing metadata, normalized scores, quality confidence, deterministic diversification, all exclusions, revision changes, cross-user isolation, concurrent mutation during candidate retrieval, cache reuse, authenticated/verified/account-access policies, no-store headers and bounded failure. Catalog covers token/validation, cache-only references, bounded cached provider pages, deduplication, empty results, failures and actual writing-role capture. Existing Home and Discover regression suites remain part of the full checks.

## Measurements

The benchmark in `RecommendationsTest::test_cold_warm_measurements_and_constant_query_count` reports real elapsed times and SQL counts for fake HTTP + in-memory SQLite. Stage instrumentation logs only durations and a cache-hit flag, no identities/preferences. These figures measure application processing and contract validation, **not live TMDB or production database latency**. Cold requests make two bounded Catalog HTTP calls (metadata + candidate pool); warm requests make zero. Core performs nine SQL queries in both fixture cases, independent of candidate count.

Full suites: Core **461 passed / 2 skipped (4040 assertions)**; Catalog **143 passed / 3 skipped (595 assertions)**; frontend **247 passed across 17 files**. Lint, TypeScript, production build and `git diff --check` passed. PHP changed files were formatted with Pint. Existing skipped integration/environment tests remain skipped; these totals do not establish live-provider acceptance.

Measured focused run (2026-11-13): request elapsed **125.72ms cold / 3.86ms warm**, nine SQL queries each. Service stages:

| Stage | Cold ms | Warm ms |
| --- | ---: | ---: |
| Activity and preference retrieval | 1.876 | .576 |
| Catalog candidate retrieval/validation | 116.415 | 0 (cached) |
| Filtering including final authoritative exclusion read | 1.373 | .669 |
| Scoring and diversification | 1.961 | 0 (cached) |
| Section assembly | .052 | .035 |
| Total service time | 121.770 | 1.296 |

These are observed fixture timings, not a claimed production speedup. Live provider, large user histories and concurrent production cache behavior need environment acceptance. There are no schema/configuration deployment steps beyond the existing service connection/cache configuration; optional Core TTL configuration is described in the contract.
